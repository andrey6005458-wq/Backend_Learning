Ответь на вопросы — определись с архитектурой и стеком

⌄

❓ Вопросы, на которые надо ответить до строчки кода

  • Какую задачу решаю? В одном предложении. Если не можешь — ещё не готов.
  • Кто пользователь? Один человек? Команда? Миллион?
  • Монолит или микросервисы? Для 99% проектов — монолит. Микросервисы — когда команда 20+ и есть реальная боль.
  • Какая нагрузка? 10 RPS или 10 000 RPS? От этого зависит стек.
  • Есть ли команда? Один — монолит + простота. Команда — микросервисы могут помочь.
  • Какой срок? MVP за 2 недели или продукт на годы?
  • Реляционная БД или NoSQL? По умолчанию — PostgreSQL. Нужен гибкий JSON — PostgreSQL JSONB. Нужны документы — MongoDB.
  • Синхронный или асинхронный? FastAPI + async — стандарт. Django — sync, но проще.
  • Куда деплоить? VPS за €4, облако, K8s? Начинай с VPS.
  • Какой бюджет? VPS €4–20/мес — хватит на годы.
⚠️ Антипаттерн: «Начну с микросервисов, Kafka, K8s, чтобы сразу как в Google». Нет. Google начинал с монолита на Python. Сначала — рабочая MVP на монолите. Потом — рефакторинг.
Реши: монолит или микросервисы Архитектура
Монолит — один процесс, одна БД, один деплой. Микросервисы — много процессов, много БД, много деплоев, нужен K8s.

Правило: начинай с монолита. Разбивай на сервисы, когда больно (команда мешает, деплой страшный, модуль тормозит других).
Почему: Instagram, Twitter, Stack Overflow — миллионы пользователей на монолитах. Микросервисы — не про масштаб, а про команду.
Выбери фреймворк Архитектура
FastAPI — async, Pydantic, автодоки, современно. Django — батарейки в комплекте (ORM, админка, auth). Flask — минимализм.

Для backend + API — FastAPI.
Выбери БД Архитектура БД
По умолчанию — PostgreSQL. Нужна гибкость JSON — PostgreSQL JSONB. Нужны документы — MongoDB. Кеш — Redis. Очереди — RabbitMQ/Kafka (позже).

Настройка окружения и конфигурации

.env, Settings, config, логгирование

⌄
Создай .env и .env.example Python
.env.example — коммитим (без секретов). .env — не коммитим (с секретами).
# .env.example POSTGRES_USER=app_user POSTGRES_PASSWORD=change_me POSTGRES_HOST=localhost POSTGRES_PORT=5432 POSTGRES_DB=project_manager
Напиши config.py через pydantic-settings Python
from pydantic_settings import BaseSettings, SettingsConfigDict class Settings(BaseSettings): postgres_user: str = "app_user" postgres_password: str = "secret" postgres_host: str = "localhost" postgres_port: int = 5432 postgres_db: str = "project_manager" model_config = SettingsConfigDict( env_file=".env", env_file_encoding="utf-8", case_sensitive=False, ) @property def database_url(self) -> str: return ( f"postgresql+psycopg://{self.postgres_user}:{self.postgres_password}" f"@{self.postgres_host}:{self.postgres_port}/{self.postgres_db}" ) settings = Settings() DATABASE_URL = settings.database_url
Почему pydantic-settings: валидация типов, автозагрузка из .env, автодополнение в IDE. Стандарт FastAPI.
Настрой логирование Python
В проде — не print, а logging. Уровни: DEBUG, INFO, WARNING, ERROR.
import logging logging.basicConfig( level=logging.INFO, format="%(asctime)s [%(levelname)s] %(name)s: %(message)s", ) logger = logging.getLogger(__name__)

База данных

Docker, Postgres, engine, session, Base

⌄
Создай docker-compose.yml для PostgreSQL Docker
services: db: image: postgres:16 container_name: project_manager_db restart: unless-stopped environment: POSTGRES_USER: ${POSTGRES_USER} POSTGRES_PASSWORD: ${POSTGRES_PASSWORD} POSTGRES_DB: ${POSTGRES_DB} ports: - "5432:5432" volumes: - pgdata:/var/lib/postgresql/data healthcheck: test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"] interval: 5s timeout: 5s retries: 5 volumes: pgdata:
docker compose up -d docker compose ps # должен быть healthy
Создай engine.py БД
from sqlalchemy import create_engine from app.database.config import DATABASE_URL engine = create_engine( DATABASE_URL, echo=True, # логировать SQL (для разработки) pool_size=5, max_overflow=10, pool_timeout=30, pool_recycle=1800, pool_pre_ping=True, )
Почему один engine: пул соединений переиспользуется. pool_pre_ping — проверка живости. pool_recycle — пересоздание idle-соединений.
Создай Base для ORM-моделей БД
# app/models/base.py from sqlalchemy.orm import DeclarativeBase class Base(DeclarativeBase): """Общий базовый класс для всех ORM-моделей.""" pass
Создай первую модель БД
# app/models/user.py from sqlalchemy import String from sqlalchemy.orm import Mapped, mapped_column from app.models.base import Base class User(Base): __tablename__ = "users" id: Mapped[int] = mapped_column(primary_key=True) name: Mapped[str] = mapped_column(String(100)) email: Mapped[str] = mapped_column(String(255), unique=True)
Создай session_getter (зависимость для FastAPI) БД
from collections.abc import AsyncGenerator from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker from app.database.engine import engine async_session_maker = async_sessionmaker(engine, expire_on_commit=False) async def session_getter() -> AsyncGenerator[AsyncSession, None]: async with async_session_maker() as session: yield session
Подключи Alembic (миграции) БД
uv add alembic alembic init alembic # настрой alembic/env.py — импортируй Base и укажи target_metadata alembic revision --autogenerate -m "create users" alembic upgrade head
Почему Alembic: изменения схемы БД версионируются. Без этого — прод сломается при изменении модели.

API и ручки

Pydantic-схемы, роутеры, CRUD, валидация

⌄
Создай Pydantic-схемы API
Схемы — что приходит и уходит через API. Отдельно от ORM-моделей.
# app/schemas/user.py from pydantic import BaseModel, ConfigDict, EmailStr class UserBase(BaseModel): name: str email: EmailStr class UserCreate(UserBase): pass class UserRead(UserBase): id: int model_config = ConfigDict(from_attributes=True) class UserUpdate(BaseModel): name: str | None = None email: EmailStr | None = None
Почему отдельно: ORM-модель — структура БД. Схема — структура API. Они не всегда совпадают (пароли, внутренние поля).
Создай CRUD-функции API БД
# app/crud/user.py from sqlalchemy import select from sqlalchemy.ext.asyncio import AsyncSession from app.models.user import User from app.schemas.user import UserCreate async def create_user(session: AsyncSession, data: UserCreate) -> User: user = User(**data.model_dump()) session.add(user) await session.commit() await session.refresh(user) return user async def get_user(session: AsyncSession, user_id: int) -> User | None: return await session.get(User, user_id) async def list_users(session: AsyncSession) -> list[User]: result = await session.execute(select(User)) return list(result.scalars().all())
Почему отдельный CRUD: бизнес-логика отделена от роутеров. Легче тестировать, переиспользовать.
Создай роутер API
# app/api/users.py from fastapi import APIRouter, Depends, HTTPException, status from sqlalchemy.ext.asyncio import AsyncSession from app.crud import user as crud from app.database.session import session_getter from app.schemas.user import UserCreate, UserRead router = APIRouter(prefix="/users", tags=["Users"]) @router.post("/", response_model=UserRead, status_code=status.HTTP_201_CREATED) async def create_user( data: UserCreate, session: AsyncSession = Depends(session_getter), ): return await crud.create_user(session, data) @router.get("/{user_id}", response_model=UserRead) async def get_user( user_id: int, session: AsyncSession = Depends(session_getter), ): user = await crud.get_user(session, user_id) if not user: raise HTTPException(status_code=404, detail="User not found") return user
Собери всё в main.py API
# app/main.py from contextlib import asynccontextmanager from fastapi import FastAPI from app.api.users import router as users_router from app.models.base import Base from app.database.engine import engine @asynccontextmanager async def lifespan(app: FastAPI): # startup async with engine.begin() as conn: await conn.run_sync(Base.metadata.create_all) yield # shutdown await engine.dispose() app = FastAPI(title="Project Manager", lifespan=lifespan) app.include_router(users_router, prefix="/api/v1") @app.get("/health") async def health(): return {"status": "ok"}
Запусти и проверь Swagger API
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000 # открой http://localhost:8000/docs
Почему Swagger: FastAPI сам генерирует документацию. Try it out — можно тестировать API прямо из браузера.

Dockerfile, compose, CI/CD, VPS

⌄
Создай Dockerfile для приложения Docker
FROM python:3.13-slim WORKDIR /app COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /usr/local/bin/ COPY pyproject.toml uv.lock ./ RUN uv sync --frozen --no-dev COPY . . ENV PATH="/app/.venv/bin:$PATH" EXPOSE 8000 CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
Добавь app в docker-compose.yml Docker
app: build: . container_name: project_manager_app restart: unless-stopped depends_on: db: condition: service_healthy ports: - "8000:8000" environment: POSTGRES_HOST: db # имя сервиса, не localhost! POSTGRES_PORT: 5432 POSTGRES_USER: ${POSTGRES_USER} POSTGRES_PASSWORD: ${POSTGRES_PASSWORD} POSTGRES_DB: ${POSTGRES_DB}
Почему db а не localhost: внутри Docker-сети контейнеры общаются по именам сервисов.
Создай .dockerignore Docker
.venv/ __pycache__/ *.pyc .git/ .env .idea/ .vscode/ tests/ *.md
Почему: без .dockerignore Docker отправит весь проект в контекст сборки — медленно, много.
